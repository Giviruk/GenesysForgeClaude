# Проверка навыков групп миньонов

Проверено 12.10.2026 по дереву `cdfdfa6` (`origin/master`). Дерево приложения в исходной
ветке `feature/gen-ui-bestiary-redesign` совпадало с ним. План проверки:
[minion-skill-rules-audit.md](../roadmap/tasks/minion-skill-rules-audit.md).

## Результат

Основная формула навыков групп миньонов реализована правильно: ранг перечисленного
в профиле навыка равен числу оставшихся миньонов минус один. Пул навыка и пул структурной
атаки используют одну формулу. Потери от ран учитываются в открытом статблоке Game Table.

Воспроизведён отдельный дефект каталога/сопоставления: у `reanimate` навык атаки
«Ржавый клинок» записан как `Melee`, которого нет в справочнике Terrinoth. Поэтому
пул этой атаки отсутствует и кнопка атаки на игровом столе выключена. Это не ошибка
формулы группового ранга.

**Решение владельца 12.10.2026:** уменьшение ран через границу потери продолжает
возвращать миньона и повышать ранги группы. Это согласованное поведение; менять его
или добавлять отдельный учёт необратимых потерь по результатам этого аудита не требуется.

## Источники и проверяемое правило

- Локальный `Genesys Corebook RUS - Vector.pdf`, страницы книги 19 (базовый пул),
  132 (миньоны) и 134 (профили). PDF находится в gitignored `_books/` и не включён в PR.
  Страницы 19 и 132 просмотрены также после рендеринга.
- [EDGE Studios: Genesys Foundry Style Guide](https://help.drivethrurpg.com/hc/en-us/articles/12723258880919-EDGE-Studios-Genesys-Foundry-Style-Guide),
  раздел Adversary Profiles and Player Rules: профиль миньона хранит групповые навыки
  без индивидуальных рангов.
- [Официальный Genesys Gen Con 2017 Adventure](https://cdn.svc.asmodee.net/production-edge/uploads/freebies/genesys/genesys_gencon_adventure_lowres.pdf),
  страница 17: у Reanimate среди групповых навыков указан `Melee (Light)`.
- [Genesys FAQ and Errata v1.1](https://images-cdn.fantasyflightgames.com/filer_public/36/48/364883c8-3f06-4821-9126-f50e4bec36c9/genesys_faq_and_errata_v11.pdf):
  проверен официальный FAQ; его разъяснение Blast не заменяет правило группового ранга.
- Проектный объём [ROT-MIN-04](../roadmap/tasks/rot-runtime-out-of-scope.md#rot-min-04-group-skills)
  и согласованный срез [game-table-minion-casualties.md](../roadmap/tasks/game-table-minion-casualties.md).
  Требования полного runtime-движка остаются за пределами текущего объёма.

Собственная краткая формализация для живой группы:

```text
N = количество оставшихся миньонов
R = max(0, N - 1), если навык перечислен в профиле; иначе R = 0
C = характеристика одного миньона для выбранного навыка
Proficiency = min(C, R)
Ability = max(C, R) - Proficiency
```

Размер группы не умножает характеристику. Один миньон имеет ранг 0; ноль миньонов
блокирует новый бросок из статблока. Искусственного ограничения ранга группы до 5
в ROT-MIN-04 нет: проверены также шесть и семь участников.

## Воспроизведённый дефект: атака реаниматора

При вызове текущих utils с данными встроенного профиля `reanimate` и справочником
Terrinoth для группы из трёх:

- Мощь 2, групповой `Melee (Light)` → ранг 2 и две жёлтые кости.
- «Ржавый клинок», `skill = Melee` → `skillLabel = null`, `pool = null`.
- «Изношенный лук», `skill = Ranged` → две жёлтые кости, расчёт корректен.

Причина: [bestiary.catalog.json](../backend/src/GenesysForge.Infrastructure/Persistence/SeedContent/bestiary.catalog.json),
строка 6426, не совпадает с набором навыков `TerrinothSkills` в
[SeedData.cs](../backend/src/GenesysForge.Infrastructure/Persistence/SeedData.cs), строки 1442–1444.
[resolveWeaponSkillName](../frontend/src/utils/labels.ts) умеет переходить от уточнённого
имени к базовому, но не выбирать `Melee (Light)` для входящего `Melee`.

Практическое следствие подтверждается условием `disabled={!attack.pool || !canAct}`
в GameTableNpcStatblock, строка 193. Из 15 встроенных minion-профилей и 25 структурных
атак это единственная атака с неопределённым пулом при сопоставлении с RoT reference.
Следующее исправление должно разрешить соответствие навыка атаки её профилю;
менять формулу `N - 1` для этого не нужно. В этом PR исправление не выполняется.

## Ограничения, которые влияют на фактический бросок

- **Уже открытый дайсроллер сохраняет прежний пул.**
  [dice-roller-context.tsx](../frontend/src/dice-roller-context.tsx), строки 20–29,
  хранит готовый request; [DiceRoller.tsx](../frontend/src/components/DiceRoller.tsx),
  строка 77, создаёт локальное состояние кубиков. Если открыть бросок при трёх
  миньонах, затем изменить раны до потери одного, статблок обновится, а ранее
  открытый дайсроллер останется с пулом для трёх. Для актуального пула нужно заново
  нажать кнопку броска из статблока либо поправить кубики вручную.
- **Счётчик критов сам по себе не снимает миньонов.**
  [UpdateParticipant.cs](../backend/src/GenesysForge.Application/Features/GameTable/UpdateParticipant.cs),
  строка 72, меняет только `CriticalInjuries`. Расчёт остатка это поле не читает.
  При N=3, WT=4, wounds=0, criticalInjuries=1 остаются три миньона и ранг 2.
  Автоматическое применение правила критической травмы группы —
  `Not found in current codebase`. В текущем ручном режиме нужно внести также
  соответствующие раны; ROT-MIN-05 остаётся вне скопа.
- **Неоднозначный legacy snapshot не позволяет определить потери.**
  При `total WT % count != 0` domain возвращает null, а
  [gameTable.ts](../frontend/src/utils/gameTable.ts), строка 67, использует исходное
  число группы. Например, count=3, total WT=10, wounds=9 всё ещё даёт ранг 2.
  Это fallback без достоверного индивидуального WT; результат не подтверждает
  фактическую численность такой группы.
- **Создание MinionGroup не проверяет вид исходного NPC.**
  [ParticipantFactory.cs](../backend/src/GenesysForge.Application/Features/GameTable/ParticipantFactory.cs)
  и [EncounterParticipantFactory.cs](../backend/src/GenesysForge.Application/Features/Encounters/EncounterParticipantFactory.cs)
  выбирают MinionGroup по количеству/запрошенному типу без проверки `NpcKind.Minion`.
  Для ошибочно созданной группы соперников/немезид `effectiveNpcSkillRanks`
  продолжит использовать их сохранённые ранги. Правильный расчёт подтверждён
  для групп настоящих миньонов.

Согласованное возвращение миньона при уменьшении ран не включается в этот список
проблем и не предлагается к изменению.

## Проверки

- Vitest: `npcStats.test.ts`, `gameTable.test.ts` — **24/24 прошли**.
- Vitest: `GameTableTab.test.tsx` — **22/22 прошли**, включая пересчёт пула
  в открытом статблоке после раны и передачу группового пула в атаку.
- xUnit: `MinionGroupRulesTests` — **8/8 прошли**.
- xUnit: `GameTableTests.MinionGroup_RemainingCount_FollowsAppliedWounds` — **6/6 прошли**.
- Прямые вызовы текущих TypeScript utils без изменения исходников: размеры 1–7,
  границы 0/4/5/8/9/12/13 ран, неперечисленный навык, critical-only update,
  уменьшение ран через границу и неоднозначный snapshot.
- Прямой прогон встроенных minion-профилей через `npcSkillViews` и `npcAttackViews`:
  15 профилей, 25 атак, один неопределённый пул, описанный выше.

Использованы уже установленные зависимости; новые пакеты не ставились. Backend
собран с `--no-restore`; имеющиеся предупреждения nullable/analyzers не помешали
целевым тестам. Полный test suite для документационного PR не запускался.
Seed, приложение, API, persistent model и миграции не изменены. Текст отчёта состоит
из собственных формулировок и структурных числовых примеров.
