## Остаток / решения

Production не изменялся: проверка выполнялась SELECT внутри BEGIN READ ONLY в обоих стеках.
По результату требуется миграция данных; ложное допущение об отсутствии legacy записей снято.
Наборы разных кампаний одного персонажа объединяются согласно существующей модели;
Character.RulesCampaignId и версии исключены пользователем. По решению пользователя после ревью мастер подключает исходный набор игрока
по shared token; владелец и ID определений сохраняются.

SQL обеих миграций проверен на PostgreSQL 17.11 во временных таблицах с search_path=pg_temp
и ROLLBACK: backfill участников исключает мастера и выбирает ранний JoinedAt; перенос всех
шести типов custom сохраняет ID, пропускает built-in/уже связанные определения, повторный
запуск не создаёт новые наборы. Рабочие таблицы не изменялись.
До ревью тест использовал копию и создавал дубли; после решения пользователя подключается
исходный набор, и ранги развиваются на прежних ID. Защита индекса CareerSkills.BuildNameIndex
остаётся для уже существующих одинаковых имён при обычном импорте личных копий.

Полная проверка 07.10.2026: 759 domain + 905 API тестов, 482 frontend теста; build и lint
пройдены. `dotnet ef migrations has-pending-model-changes --no-build` не обнаружил изменений
модели без миграции; сгенерированы SQL scripts для AddCampaignMembers и PackLegacyCustomContent.
Остаток реализации отсутствует; остаётся review/merge PR и отдельная выкатка оператором.
