## Контекст

Владелец сообщил о большой задержке между нажатием кнопки и реакцией интерфейса. Замер перехватом
`fetch` в работающем приложении показал, что на одно действие уходит **три последовательных**
обращения к серверу:

```
PATCH /characters/{id}/mounts/{id}    30 ms    0 KB   старт +1 ms
GET   /characters/{id}                15 ms   79 KB   старт +144 ms  ← ждёт PATCH
GET   /reference/RealmsOfTerrinoth    31 ms  560 KB   старт +172 ms  ← ждёт лист
                                                      → перерисовка на 261 ms
```

Вычисления ни при чём: разбор 560 КБ JSON — 3.6 мс, эндпоинты в тёплом состоянии 30/15/31 мс.
Проблема в структуре ожиданий, и она умножает на три любую сетевую задержку.

## Что сделано

- [x] **Кэш справочника на сессию** в `api.reference`. Справочник — каталог игры (132 предмета,
      112 талантов, 80 качеств…), он не зависит от действий с персонажем, но перезапрашивался после
      каждого клика: ~560 КБ и около десятка запросов в БД. Ключ — тот же URL, что уходит на сервер,
      поэтому система и контекст (персонаж, кампания) учитываются сами собой. Хранится Promise, а не
      результат: одновременные запросы склеиваются в один.
- [x] **Инвалидация центральным правилом** в `request()`, а не перечислением методов: сбрасываем на
      любом успешном не-GET, кроме правок самого персонажа. Плюс сброс в `tokenStorage.clear()` —
      у следующего пользователя свой кастомный контент.
- [x] **Лист показывается сразу**, не дожидаясь справочника: `setSheet` вызывается на первом ответе,
      а не вместе с `setReference` после второго.
- [x] Тесты: 8 новых Vitest на кэш (попадание, раздельные ключи по системе и контексту, склейка
      одновременных запросов, правка персонажа не сбрасывает, правка каталога сбрасывает, ловушка с
      homebrew-паком, неудачная правка не сбрасывает, провалившийся запрос не залипает, конец сессии
      чистит).
- [x] Проверки: frontend 250 Vitest + tsc + eslint, замер до/после в браузере, ручная проверка
      инвалидации через реальный UI.
- [x] PR открыт.

## Результат замера

Один и тот же сценарий (персонаж с 30 предметами и транспортом, медиана из 4 кликов, localhost):

| | было | стало |
|---|---:|---:|
| запросов на клик | 3 | **2** |
| передано на клик | ~639 КБ | **77 КБ** |
| время на localhost | ~53 мс | **~40 мс** |

На localhost выигрыш во времени скромный: RTT там нулевой. Ценность в убранном round-trip — на
проде он стоит реальных денег, см. ниже.

## Что осталось / блокеры

- **Третий шаг предложения не сделан: мутации по-прежнему возвращают `204 NoContent`.** Он убрал бы
  ещё один round-trip (2 → 1), но это 36 эндпоинтов и 123 проверки статуса в тестах, то есть
  изменение публичного контракта API — по AGENTS.md отдельное решение владельца, а не часть правки
  производительности. Вынесено в отдельный разговор с этими числами.
- **Задержка сервера на проде — вторая, независимая проблема.** Замер публичного
  `/api/auth/providers` (86 байт, без БД) при **уже установленном** соединении:
  `ttfb=0.520s / 0.504s / 0.327s / 0.256s`. Четверть-полсекунды на запрос-пустышку — это не код
  приложения. Плюс `cf-cache-status: DYNAMIC` даже на SPA-шелле: Cloudflare не кэширует ничего.
  Кандидаты: VPS делит ресурсы со вторым проектом, отсутствие keep-alive до origin, синхронная
  запись логов. Замеры сделаны с машины разработчика (edge FRA), сетевой путь владельца другой.
- **`CharacterLoader` тянет восемь коллекций одним запросом без `AsSplitQuery()`** — на PostgreSQL
  это декартово произведение. На in-memory провайдере не воспроизводится, поэтому проверять надо на
  реальной БД; в объём этой правки не входит.

## Заметки / решения

- Правило инвалидации написано от обратного намеренно: перечислять по одному два десятка методов,
  меняющих каталог, значит однажды забыть новый и показать игроку устаревший справочник. Лишний
  сброс стоит один запрос, пропущенный — это баг.
- В правиле есть ровно одно исключение, и оно неочевидное: `PUT /api/characters/{id}/homebrew-packs/{packId}`
  висит на персонаже, но меняет состав справочника. Проверка по одному префиксу `/characters/` его
  бы пропустила. Ловушка закреплена отдельным тестом.
- `refresh` оставлен в стиле промис-цепочки, а не `async/await`: правило `react-hooks/set-state-in-effect`
  видит `setState` в async-функции, вызываемой из эффекта, и падает. Поведение при этом то же.
- Провалившийся запрос справочника удаляется из кэша — иначе одна сетевая ошибка залипла бы на всю
  сессию.
