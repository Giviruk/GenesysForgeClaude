## Контекст

Три замечания владельца по вкладке «Ремесло»:

1. Руну можно было выбрать в ремесле. В списке «Что делаем» их не было (отбор по цене и
   редкости), но вкладка «Зачарование» брала основу из инвентаря без фильтра, а сервер для
   `CraftingKind.Enchantment` выходил из `EnsureCraftable` до всех проверок.
2. Выбор «Изготовление / Варка / Зачарование» был радиокнопками вместо табов.
3. Флажок «Грубая работа» растягивался на всю карточку.

Отдельно выяснилось, откуда во вкладке брались «Рунический мороз» и «Рунический гром»: 21
улучшение вынесено из каталога снаряжения в свой тип контента ещё в 62d25cc, но
`RetireBuiltinsMissingFromSeed` вызывался только для карьер и навыков. В уже засиженной базе
строки-предметы остались активными, с ценой и редкостью — то есть валидной целью изготовления и
товаром витрины. На чистой базе их нет, поэтому тесты этого не ловили.

## Заметки / решения

- `crafting.base_not_enchantable` — новый reason code; зачарование по-прежнему не создаёт запись
  каталога, поэтому цена цели ему не нужна, но руна и реликвия основой не бывают.
- Отбор основ в UI сделан исключением, а не разрешением: незнакомая своя запись остаётся доступной.
- `RetireBuiltinsMissingFromSeed` для предметов идёт по тому же натуральному ключу `(System, Name)`,
  что и `SeedMissing`, — переименование записи в каталоге ведёт себя как у карьер и навыков.
- Экземпляры игроков не теряются: их переносит `MigrateLegacyAttachmentItems`, а Retired-строка
  остаётся в БД ради ссылок из экспортов.
- Проверки: backend 732 domain + 831 API, frontend 290 Vitest, lint и production build — passed.
