## Контекст

Магазин и инвентарь уже рассчитывают цену экземпляра по `WeaponCraftsmanship` для оружия/брони и по `ImplementMaterial` для магических инструментов. В ремесле эти параметры не выбираются: стоимость компонентов берётся от базовой цены, а результат создаётся с `Steel`/`Oak`.

## Заметки / решения

- Assumption: под материалами обычного снаряжения понимается существующая typed-модель `WeaponCraftsmanship`, применимая к оружию и броне; для прочих предметов коэффициентов материалов в текущем коде нет.
- Для магического инструмента используется существующая typed-модель `ImplementMaterial` и errata-множители.
- Зачарование не меняет материал готовой основы; оно использует уже сохранённую цену экземпляра.
- Покупка уже пересчитывалась на backend и в UI; добавлен сквозной frontend-регрессионный тест,
  который проверяет показанную сумму и параметры запроса для обычного и магического снаряжения.
- Проверки: backend 740 domain + 841 API; frontend 312 тестов, lint и production build; SQL
  обновления и отката миграции успешно генерируется, legacy-значения — Steel/Oak.
