# Адаптивный лист персонажа (responsive-character-sheet)

- **Пункт ТЗ:** P2-3 — улучшить мобильную адаптацию, этап 2: лист персонажа
- **Ветка:** `feature/responsive-character-sheet`
- **Базовая ветка:** `master`
- **Статус:** 🚧 In progress — мобильная полировка по обратной связи Pixel 10 Pro

## Контекст

После адаптивного shell следующий узкий приоритет — приватный лист персонажа. На desktop лист использует плотную шапку, длинную горизонтальную группу вкладок, сетку характеристик и две таблицы навыков. На телефоне эти блоки должны оставаться читаемыми и доступными для touch/keyboard-навигации без горизонтального скролла всей страницы.

## Зафиксированные требования

- Проверить целевые ширины: 360px, 390px, 430px и 768px.
- Шапка листа должна корректно переносить имя, систему, XP и действия.
- На desktop вкладки остаются обычной группой; на маленьких экранах они собираются в компактный выпадающий список.
- Характеристики и производные показатели должны собираться в читаемую сетку.
- Таблицы навыков на телефоне должны превращаться в карточки с понятными подписями полей.
- Кнопки броска/покупки/изменения должны иметь touch-friendly размер.
- Кнопки «Завершить создание» и дополнительные действия должны находиться на уровне имени персонажа, справа от него, без растягивания на всю ширину.
- Карточки навыков на маленьких экранах должны быть компактнее, иметь внутреннюю двухколоночную мета-разметку и заметный зазор между карточками.
- Не должно быть горизонтального overflow у всей страницы.
- Не менять бизнес-логику, API, auth, seed, package versions и deployment files.

## Критерии приёмки

- На desktop sidebar и текущая плотная компоновка сохраняются.
- На телефоне страница не получает горизонтальный scroll.
- Заголовок персонажа, XP и действия доступны без обрезания.
- На телефоне текущая вкладка выбирается через выпадающий список.
- В карточке навыка видны название, характеристика, карьерность, ранги, пул и действия.
- Модальные/вложенные состояния листа не выходят за viewport.

## Что осталось / блокеры

Пользовательская проверка на Google Pixel 10 Pro выявила три конкретные проблемы: действия в шапке растягивались и уходили вниз, длинная группа вкладок требовала горизонтального скролла, а карточки навыков были слишком крупными и близко расположенными. Реальный Pixel-аудит после этой правки остаётся обязательным.

## Заметки / решения

- Существующие page-level responsive rules сохраняются, новые правила добавляются в конце CSS как прицельные overrides.
- На этом этапе не меняем API, состояние листа и обработчики действий; меняем только структуру presentation markup и CSS-адаптацию.
- Для desktop сохранена исходная группа кнопок-вкладок; dropdown включается только в mobile breakpoint.
- Точка компактности skill cards выбрана как `max-width: 30rem`, чтобы покрыть ширину Pixel 10 Pro и близкие телефоны.
- Базовый CI run #584 для предыдущего responsive-PR был успешен; для этой полировки нужно прогнать новый CI после обновления PR #238.
