## Контекст

Backend (`TalentChoiceSchemas`) требует выбор при покупке ранга у девяти талантов, но `TalentsTab`
открывает форму выбора только для Dedication и Animal Companion. Остальные отправляют пустой
`choices` и получают `talent.choice.required` («Для этого ранга нужно сделать выбор (N).») без
возможности что-то выбрать.

Затронутые таланты (по схеме `TalentChoiceSchemas`):

| Талант | Выбор |
|---|---|
| Квалификация (Knack for It) | навык: ранг 1 — один, далее по два; не боевые и не магические; без повторов |
| Одарённость (Natural) | два разных навыка |
| Мастер (Master) | один навык |
| Счастливое попадание (Lucky Strike) | одна характеристика |
| Героическое восстановление (Heroic Recovery) | одна характеристика |
| Героическая воля (Heroic Will) | две разные характеристики |
| Коронное заклинание (Signature Spell) | магическое действие + непустой мультисет дополнительных эффектов |

Прочие таланты со словом «выберите» в описании выбирают цель во время игры, а не при покупке,
поэтому схемы не требуют.

## Заметки / решения

- Схема БД не меняется: `CharacterTalentChoices` уже хранит выбор по рангу, миграция не нужна.
- Значение выбора Signature Spell — `Действие|Эффект|Эффект…` по стабильным `NameEn`, эффекты
  отсортированы: порядок не важен, кратность важна.
- Покупка второго ранга таланта с выбором падала с 500 (`DbUpdateConcurrencyException`): выбор
  добавлялся только в навигацию уже отслеживаемого таланта, и EF принимал его за существующую
  запись. Затрагивало Knack for It, Dedication и Animal Companion.
- Вне объёма: таланты с `NeedsChoice` (legacy) по-прежнему нельзя «починить» из интерфейса —
  repair-сценария в коде нет.
- Проверки: backend Domain 759 / API 880; frontend 457 тестов, lint, production build. Вручную в
  приложении (API in-memory + vite): куплены «Героическая воля», «Квалификация» (ранги 1–2) и
  «Коронное заклинание» через новые формы.
