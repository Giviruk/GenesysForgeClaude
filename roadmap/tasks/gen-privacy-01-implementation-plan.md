## Проверенные настройки на 9 октября 2026 года

Проверка выполнена чтением VPS, без изменений конфигурации, удаления данных и деплоя.

| Данные | Фактическая настройка | Проверка |
|---|---|---|
| Локальные backups | BACKUP_RETENTION_DAYS=14; find -mtime +14 раз в сутки. Из-за округления и периодичности возраст может достигать 16 дней | env работающего genesysforge-backup и его Config.Cmd |
| S3 старый путь | Enabled, expiration 4 дня для genesysforge/backups/ | подписанный GET bucket?lifecycle на Beget |
| S3 текущий путь | backup/genesysforge/ не покрыт правилом; автоматического срока нет | Config.Cmd работающего backup + тот же lifecycle XML |
| Журналы API/web обеих версий и Ariadne | json-file, Config={}, daemon.json отсутствует; внешнее logrotate-правило для docker/json.log не найдено | docker inspect, /etc/docker и /etc/logrotate* |
| События Ariadne, проект GenesysForge | raw_event_retention_days=180; RetentionWorker удаляет только events каждые 6 часов | SELECT name, raw_event_retention_days FROM projects; исходник реально развёрнутого commit 7b12969e9da27810e15ea7bc26d5432edf85e711 |
| Посетители/сессии/identities Ariadne | Worker не удаляет эти таблицы; автоматического срока нет | AnalyticsServices.cs и AnalyticsDbContext.cs той же редакции |

Источники: [production compose](../../docker-compose.prod.yml),
[инфраструктурный план backups](https://github.com/Giviruk/vps-infra/blob/main/docs/backups.md),
[Ariadne retention в развёрнутой редакции](https://github.com/Giviruk/ariadne/blob/7b12969e9da27810e15ea7bc26d5432edf85e711/src/Ariadne.Api/AnalyticsServices.cs).
Репозиторий описывает 4 дня для S3, но серверное правило покрывает только старый путь.
Поэтому политика не обещает этот срок для новых копий. Dozzle — просмотр логов, а не их ротация.

## Что документами и этим PR не закрывается

- [ ] **Подать уведомление РКН.** Владелец подтвердил, что оно ещё не подано.
  Для автоматизированного веб-сервиса оснований для исключений из ч.2 ст.22 не установлено:
  остались обработка в государственных системах для безопасности/порядка,
  исключительно неавтоматизированная обработка и транспортная безопасность.
  Бесплатность и статус физлица не освобождают. Уведомление требует ФИО и адрес оператора,
  целей, категорий субъектов/данных, оснований, мер защиты, мест БД и других фактических сведений.
  Сведения реестра общедоступны, кроме сведений о средствах безопасности (ч.4 ст.22).
  Отсутствие ФИО в политике не скрывает его в реестре.
  [Ст.22 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/d996966e22e1320c9de1ab82d9f6be12c3d9d765/).
- [ ] **Согласовать и применить срок S3 для текущего пути.** Конкретное исправление:
  сохранить правило старого пути и добавить Enabled / Prefix=backup/genesysforge/ /
  Expiration.Days=4. Предварительно подтвердить требуемый срок и последствия удаления;
  проверить загрузку и восстановление. Применение запускает удаление копий, поэтому не выполняется
  в рамках запроса на чтение сервера. До применения действует описанный ручной режим.
- [x] **Настроить ограничение журналов.** В `docker-compose.prod.yml` всем семи сервисам
  задан `json-file` с `max-size=10m`/`max-file=3` (якорь `x-logging`). Это ограничение объёма,
  а не число дней. Вступает в силу при деплое: `up -d` один раз пересоздаёт все контейнеры,
  включая обе БД (короткий перезапуск).
- [ ] **Перед слиянием — правило S3 владельцем.** Политика (§3) обещает «не дольше 16 дней»
  для резервных копий; без правила для `backup/genesysforge/` это неверно. Скрипт применения
  выполняет владелец с ключом бэкап-бакета; ключ в репозиторий и чат не передаётся.
- [ ] **Удаление данных Ariadne.** Реализовать/согласовать очистку visitor/session/identity
  и журнальных связей наряду с events; сейчас требуется ручное исполнение обращений.
  Отзыв в браузере прекращает новые события, но не удаляет ранее собранные записи сервера.
- [ ] **Исполнять обращения и защиту.** Обработка запросов об удалении/доступе, включая
  общие тексты, файлы, аналитику и backups; меры защиты, договоры с Beget и реакция на инциденты.
  Текст не создаёт эти процессы. Возможность подтвердить ранее полученное согласие должна
  оцениваться оператором: выбор в браузере не является серверным журналом доказательств.
- [ ] **Реальные персональные данные в публичных материалах.** Не подменять запретом в правилах
  отдельные основания распространения. При необходимости отдельного согласия оператору-физлицу
  нужны реквизиты по [приказу РКН №18](https://www.consultant.ru/document/cons_doc_LAW_382687/37752db178121f5758180844db843703ca3f46e5/).
- [ ] **Слияние и публикация.** Маршруты будут опубликованы после принятия PR и деплоя;
  проверка локальной сборки не означает, что действующий сайт уже обновлён.

[Ст.18.1](https://www.consultant.ru/document/cons_doc_LAW_61801/eeeebe22bf738fd65bb66b95cc278911ae2525ee/)
требует доступности политики на сайте; [ст.9](https://www.consultant.ru/document/cons_doc_LAW_61801/6c94959bc017ac80140621762d2ac59f6006b08c/)
предусматривает отдельное оформление согласия от других документов. Проверено по редакции
закона от 26.07.2026. Организационные пункты не выдаются за выполненные.

## Команды проверки

```bash
cd frontend
npm test
npm run lint
npm run build
# dev server с тестовой аналитикой (в отдельном терминале):
VITE_ARIADNE_ENDPOINT=http://analytics.test VITE_ARIADNE_PROJECT_KEY=pub_test npm run dev -- --host 127.0.0.1 --port 5189
E2E_ANALYTICS_CONSENT=1 E2E_BASE_URL=http://127.0.0.1:5189 npx playwright test e2e/privacy.spec.ts
# Из корня:
dotnet test backend/tests/GenesysForge.Api.Tests --filter 'FullyQualifiedName~AnalyticsConsentTests|FullyQualifiedName~AuthTests|FullyQualifiedName~RefreshTokenTests' --no-restore
```

Аналитический E2E использует stub tracker; на обычной конфигурации он пропускается,
публичный тест документов выполняется всегда. На этой машине Chromium выбран через
E2E_CHROMIUM_EXECUTABLE (локальный Google Chrome); в CI используется установленный Playwright browser.
